# Code structure and shared contracts

Where code lives in `server/` and `web/`, the interfaces the modules share, how to add a module, and the data rules. `docs/architecture.md` explains how the product works; `docs/status.md` says what is built. Where this file and the code differ, the code is right: fix this file.

## 1. `server/`

```
server/
├─ package.json  tsconfig.json  vitest.config.ts  drizzle.config.ts  .env.example
├─ docker-compose.dev.yml     Postgres (pgvector) and SeaweedFS for development and tests
├─ openapi.json               generated by `pnpm openapi`, committed
├─ assets/fonts/              Noto Sans and Noto Sans Devanagari, with their licence (used by the renderer)
├─ scripts/                   openapi.ts, db-reset.ts, e2e-server.ts, e2e-control.ts
├─ test/                      helpers.ts, global-setup.ts, fixtures/{base,brand,plan,research,studio}
└─ src/
   ├─ main.ts                 entrypoint: config, bucket, DBOS launch, schedules, HTTP on 127.0.0.1:PORT
   ├─ app.ts                  createApp(): the Hono app; tests and `pnpm openapi` use it
   ├─ modules.ts              the one list of module routers; imports every workflow file
   ├─ config.ts               environment, parsed with Zod; refuses development values in production
   ├─ log.ts                  pino

   ├─ db/
   │  ├─ client.ts  tenant.ts  seed.ts  migrate.ts  setup.ts

   ├─ render/                 the render engine: slide.ts, video.ts, templates/. No database access
   ├─ domain/<module>/        one folder per module; `index.ts` is its only public face
   └─ workflows/              index.ts (DBOS setup) and one file per module that runs in the background
```

Rules of the layout:

- Other modules import a module only through its `index.ts`. The reads that cross modules are `approve/studio.ts`, `publish/reads.ts` and Home's `readers`.
- Unit tests sit beside the code as `*.test.ts`. Tests that need Postgres or storage end in `*.int.test.ts`.
- `src/isolation.int.test.ts` calls every registered route with another tenant's brand and foreign IDs, and fails for a route it has no entry for (`BODY`, and `QUERY` for an ID query parameter): a new route needs an entry there. `src/seams.int.test.ts` runs one post from an approved fact to a connector through the real modules; the cross-module reads are loosely typed, so a renamed field shows only there.

## 3. Shared server contracts

```ts
// db/tenant.ts
type Tx                                             // a Drizzle transaction
withTenant<T>(fn: (tx: Tx) => Promise<T>): Promise<T>
withBrand<T>(brandId: string, fn: (tx: Tx) => Promise<T>): Promise<T>
tenantOf(tx: Tx): Promise<string>                   // the tenant ID, for objectKey
currentTenantId(): Promise<string>                  // the one tenant, from TENANT_SLUG
// Both set app.tenant_id; withBrand also sets app.brand_ids. withBrand throws NotFoundError (404)
// and writes a `denied` audit event when the brand is not in the tenant or fn throws NotFoundError.

// http/errors.ts: the app maps them to { error: { code, message } }
HttpError(status, code, message)   NotFoundError 404   ConflictError 409   ValidationError 400   BudgetError 402

// http/router.ts, http/brand.ts
createRouter()  json(schema)  errorResponse  BrandParams  BrandItemParams

// db/schema/core.ts
brandColumns                      // { tenantId, brandId } for every brand-owned table
brandPolicies(table)              // the RLS policies every brand-owned table declares
runColumns                        // { state, error, startedAt, finishedAt, estimate, actual }
runStates                         // 'running' | 'awaiting_approval' | 'completed' | 'failed_retryable' | 'failed_final' | 'cancelled'

// contracts/common.ts
Money = { usd: string; npr: string }               // decimal strings, never floats
ApprovedFact = { id, section, subjectType, subjectId, subjectName, field, value, unit, language,
                 sourceId, verifiedAt, expiresAt }

// domain/audit
audit(tx, { brandId?, actor, action, objectType, objectId, objectVersion?, result: 'ok'|'denied'|'failed', reason? }): Promise<void>
listAudit(tx, brandId, limit?)   verifyAuditChain(rows)   // each row hashes the one before it; actor is 'operator' until login exists

// domain/costs
estimateCost(model, inputTokens, maxOutputTokens): Money
remainingMonthlyCap(tx): Promise<Money>            // tenant cap from AI_MONTHLY_CAP_NPR, calendar month in UTC
recordCost(tx, CostRecord): Promise<Money>         // used by ai.extract only
brandCosts(tx, brandId)                            // month total, cap, remaining, one row per run

// ai (index.ts)
extract<T>({ brandId, runType, runId, system, parts: AiPart[], schema: z.ZodType<T>, maxOutputTokens? }):
  Promise<{ object: T; cost: Money }>
AiError { retryable }   estimateTokens(parts)   mockAi.queue(...)  mockAi.calls  mockAi.refusal  mockAi.reset()   // mock: tests only
// Reserves its estimated cost under a tenant advisory lock (BudgetError when over the cap), calls the model with no
// tools, validates the answer against the schema with one repair attempt, and settles the cost row with real usage.
// A new model is added to ai/registry.ts with its list price.

// storage
objectKey(tenantId, brandId, 'upload'|'snapshot'|'asset', id, ext)   // tenant/<t>/brand/<b>/<kind>/<id>.<ext>
putObject  getObject  objectSize  deleteObject  presignUpload  presignDownload  ensureBucket

// domain/sources
Source = { id, brandId, kind: 'page'|'upload', uri, mime, checksum, capturedAt, objectKey, text, trust, meta }
fetchPage(url)  pickPages(siteUrl, max)  savePageSource(tx, brandId, url, trust)
createUpload(tx, brandId, { filename, mime, bytes })  completeUpload(tx, brandId, sourceId)  getSource  listSources
verifyQuote(sourceText, quote): boolean   normalizeQuote(s)
fetchGuard                                         // resolve, isBlocked, minIntervalMs: tests swap and restore them

// domain/brands
listBrands  createBrand  getBrand  updateBrand  archiveBrand  listCompetitors  createCompetitor  updateCompetitor  deleteCompetitor

// domain/knowledge
approvedFacts(tx, brandId, filter?: { section? }): Promise<ApprovedFact[]>   // current, approved and not expired
readiness  listFacts  proposeFacts  approveFact  editFact  resolveConflict  getPalette  listAssets  …

// domain/approve
validApproval(tx, brandId, draftId, facts, studio?): Promise<Approval | null>   // the gate
queue  getSettings  setSettings  setPaused

// workflows/index.ts
QUEUE ('default')   APPLICATION_VERSION   executorId()   launchWorkflows()   shutdownWorkflows()
retryWorkflow(id)      // forks from the first failed step; earlier steps keep their stored output, so a paid call is not repeated
runError(e)            // what a failed run shows the owner: an HttpError or AiError message, else a plain sentence
```

Helpers and conventions:

- Imports use `.ts` extensions; Node runs the TypeScript directly. `tenant_id` defaults from the transaction, so inserts set `brandId` only.
- An `audit` with a `brandId` needs a transaction scoped to that brand; without one the event is tenant-level.
- Module routers are mounted at `/api` and declare full paths (`/brands/{brandId}/plan/…`). Pass the raw `brandId` to `withBrand`, which answers 404 for anything outside the tenant.
- Enqueue a workflow with `DBOS.startWorkflow(fn, { queueName: QUEUE })`. A schedule is applied at startup in `main.ts` (`applyResearchSchedule`, `applyPublishSchedule`).
- Tests: `testDb()` (a throwaway database `mkt_test_<random>` with a fresh tenant; also `url`, `adminUrl`, `adminQuery`, `makeBrand`), `launchTestWorkflows(t)`.

## 4. Shared web components (`components/app/`, exported from its `index.ts`)

Every module uses these and none restyles them; no module imports another module's folder.

| Component | Use |
|---|---|
| `Shell`, `PageHeader` | Layout; the active brand is always visible |
| `StateBlock` | The loading, empty, partial, error, unavailable, rate-limited and stale states (`ViewState`) |
| `StatusBadge` | Fact statuses and run states |
| `MoneyText` | An NPR amount, with USD in the title |
| `SourceQuote` | A quote with its source link or file and page |
| `CostConfirm` | Shows an estimate and the remaining monthly cap and asks for confirmation; refuses an estimate over the cap |
| `RunProgress` | Polls a run every 3 seconds; shows its state with cancel and retry |
| `Async`, `MutationError`, `viewStateOf` | A query's loading, error and stale states, and a failed write; `what` is a noun without its article |
| `useAct(root, fn)` | A write that refreshes the module's cached queries for the brand |
| `ModuleTabs`, `BackLink`, `WeekNav` | A module's sub-page tabs, the way up from a detail page, previous, this and next week |
| `Time` | An instant in the brand's timezone with the zone named |
| `CopyButton`, `LiveStatus` | Copy text and say so; a polite announcement for a change shown only by a list or badge moving |
| `BrandScope`, `useBrandId`, `useBrand`, `useBrands` | The active brand |

Also shared: `api` and `unwrap` (openapi-fetch client; `unwrap` throws `ApiError` with the base error body's code and message) from `@/lib/api/client`; date, week and money helpers in `lib/time.ts` and `lib/money.ts`; names for codes in `lib/labels.ts`; the classes `btn btn-primary|secondary|quiet`, `field`, `label`, `input`, `panel`, `num` from `app.css`. Colours come from `web/public/theme.css` through Tailwind names; no hex values in components. Type is Geist plus Noto Sans Devanagari.

## 5. Adding a module

1. Schema: `server/src/db/schema/<name>.ts`, brand-owned tables built on `brandColumns` with `...brandPolicies('<table>')`; export it from `schema/index.ts`; run `pnpm db:generate`. If the app role needs a grant beyond the defaults (for example append-only), add it to `server/src/db/setup.ts`.
2. Contracts: `server/src/contracts/<name>.ts`.
3. Domain: `server/src/domain/<name>/` with `routes.ts` (a `createRouter()` with full paths `/brands/{brandId}/<name>/…`) and `index.ts` exporting `routes` and what other modules may read.
4. Register it in `server/src/modules.ts`: import `routes` and add it to `moduleRoutes`.
5. Background work: `server/src/workflows/<name>.ts`, imported in `modules.ts`; a schedule gets an `apply…Schedule()` call in `main.ts`. Every model call inside goes through `extract`.
6. `pnpm openapi` in `server/`, then `pnpm api:types` in `web/`.
7. Web: `web/src/app/(app)/app/b/[brandId]/<name>/`, `web/src/components/<name>/`, an entry in `web/src/nav.ts`, and `@source "../../components/<name>";` in `web/src/app/(app)/app.css`.
8. Add every new route to `src/isolation.int.test.ts` (`BODY`, `QUERY`).
9. Anything that publishes calls `validApproval`. Anything that reads another module goes through its `index.ts`.

## 6. Data rules

- Every brand-owned table has `tenant_id` and `brand_id` and an RLS policy from `brandPolicies`. The app connects as `marketing_app`, which has no `BYPASSRLS`. Every query runs in `withBrand` or `withTenant`; the settings it makes are transaction-local, so a pooled connection keeps no context.
- `audit_events` and `approvals` are append-only: `setup.ts` revokes update, delete and truncate from the app role. Audit rows hash the previous row.
- Cross-brand reads go through `SECURITY DEFINER` functions in `setup.ts` (`tenant_month_cost_npr()`), which filter by tenant themselves.
- Money is a decimal string or a BigInt in fixed point, never a float. Every cost row keeps the rates and the USD to NPR rate it used.
- Object keys hold IDs only, under `tenant/<t>/brand/<b>/`, never a user's file name. Downloads other than raster images are attachments. An upload goes to `<key>.pending`; only `completeUpload` writes the real key, after checking size, magic bytes and type.
- Run tables (`runColumns`) hold the run state; a state that can be derived (an approval's validity) is worked out on every read, never stored.
- Migrations are generated from the schema; `pnpm db:reset` builds a development database from the schema directly; `drizzle-kit push` is never used because it drops RLS clauses.
- Never import `drizzle-kit/api` in a test file; it patches Array and String prototypes and breaks pdf.js. `test/global-setup.ts` generates the schema SQL once.
