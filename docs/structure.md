# Code structure and shared contracts

For every developer or agent building the Prachaar product. It fixes where code goes and which interfaces the modules share, so that modules can be built on separate branches without editing the same files. It applies the layout of `docs/stack.md` (ADR-001); where the two differ, this file wins for sprint 1.

## 1. Branches and ownership

| Branch | Built from | Owns | Plan |
|---|---|---|---|
| `product/base` | `main` | Every path tagged **base** below | `docs/superpowers/plans/2026-11-27-sprint-1-base.md` |
| `product/brand` | `product/base` | Every path tagged **brand** | `docs/superpowers/plans/2026-11-27-sprint-1-brand.md` |
| `product/research` | `product/base` | Every path tagged **research** | `docs/superpowers/plans/2026-11-27-sprint-1-research.md` |

Rules for the module branches:

1. Edit only the paths your branch owns. The base branch creates a stub for every module-owned file that a base file imports, so a module never needs to touch a base file to register itself.
2. If a base file must change, make the smallest change and list it under "Base changes" in your hand-off note.
3. Do not commit anything under `server/src/db/migrations/`. Tests apply the schema straight to a throwaway database. The migration is generated once, after the merge.
4. `server/openapi.json`, `web/src/lib/api/schema.d.ts` and both `pnpm-lock.yaml` files are generated. Commit them on your branch. After a merge they are regenerated, never merged by hand.
5. Do not add a dependency that the base already covers (section 6). If you must add one, list it in the hand-off note.
6. Commits carry no AI attribution line of any kind.

## 4. Shared server contracts

The base branch implements these. Module branches call them and do not reimplement them. Names and types are fixed; bodies are the base builder's.

```ts
// db/tenant.ts
type Tx                                             // a Drizzle transaction
withTenant<T>(fn: (tx: Tx) => Promise<T>): Promise<T>
withBrand<T>(brandId: string, fn: (tx: Tx) => Promise<T>): Promise<T>
// Both set app.tenant_id; withBrand also sets app.brand_ids. withBrand throws NotFoundError
// (HTTP 404) and writes a `denied` audit event when the brand is not in the tenant.

// http/errors.ts — the route layer maps these to the base error body
NotFoundError (404)   ConflictError (409)   ValidationError (400)   BudgetError (402)

// db/schema/core.ts
brandColumns                                        // { tenantId, brandId } for every brand-owned table
brandPolicies(table: string)                        // the RLS policies every brand-owned table declares
runColumns                                          // { state: RunState, error, startedAt, finishedAt, estimate, actual }

// workflows/index.ts
type RunState = 'running' | 'awaiting_approval' | 'completed'
              | 'failed_retryable' | 'failed_final' | 'cancelled'

// contracts/common.ts
type Money = { usd: string; npr: string }           // decimal strings, never floats
type ApprovedFact = {
  id: string; section: string; subjectType: string; subjectId: string | null;
  subjectName: string | null; field: string; value: unknown; unit: string | null;
  language: string; sourceId: string | null; verifiedAt: string; expiresAt: string | null }

// domain/audit
audit(tx: Tx, e: { brandId?: string; actor: string; action: string; objectType: string;
  objectId: string; objectVersion?: number; result: 'ok' | 'denied' | 'failed';
  reason?: string }): Promise<void>                 // actor is 'operator' until login exists

// domain/costs
estimateCost(model: string, inputTokens: number, maxOutputTokens: number): Money
remainingMonthlyCap(tx: Tx): Promise<Money>         // tenant cap from AI_MONTHLY_CAP_NPR
// cost rows are written by ai.extract, not by modules

// ai
type AiPart = { type: 'text'; text: string }
            | { type: 'file'; mediaType: string; data: Uint8Array; filename?: string }
estimateTokens(parts: AiPart[]): number
extract<T>(o: { brandId: string; runType: string; runId: string; system: string;
  parts: AiPart[]; schema: z.ZodType<T>; maxOutputTokens?: number }): Promise<{ object: T; cost: Money }>
// Checks the cap before calling (BudgetError), validates against the schema with one repair
// attempt, writes a cost_events row on success and on failure, throws AiError { retryable }.
// The model receives no tools. With AI_MODEL=mock it answers from ai/mock.ts.
mockAi.queue(...objects: unknown[]): void           // tests only
mockAi.calls: { system: string; parts: AiPart[] }[] // tests only

// storage
objectKey(tenantId: string, brandId: string, kind: 'upload' | 'snapshot' | 'asset',
  id: string, ext: string): string                  // tenant/<t>/brand/<b>/<kind>/<id>.<ext>
putObject(key: string, body: Uint8Array, contentType: string): Promise<void>
getObject(key: string): Promise<Uint8Array>
presignUpload(key: string, contentType: string, maxBytes: number): Promise<string>
presignDownload(key: string): Promise<string>       // attachment unless a raster image

// domain/sources
type Source = { id: string; brandId: string; kind: 'page' | 'upload'; uri: string; mime: string;
  checksum: string; capturedAt: Date; objectKey: string; text: string | null;
  trust: 'owner' | 'brand_site' | 'external'; meta: Record<string, unknown> }
fetchPage(url: string): Promise<{ finalUrl: string; html: string; text: string; title: string }>
pickPages(siteUrl: string, max: number): Promise<string[]>
savePageSource(tx: Tx, brandId: string, url: string, trust: Source['trust']): Promise<Source>
createUpload(tx: Tx, brandId: string, f: { filename: string; mime: string; bytes: number }):
  Promise<{ source: Source; uploadUrl: string }>
completeUpload(tx: Tx, brandId: string, sourceId: string): Promise<Source>
getSource(tx: Tx, brandId: string, id: string): Promise<Source>
listSources(tx: Tx, brandId: string): Promise<Source[]>
verifyQuote(sourceText: string, quote: string): boolean

// domain/brands
listCompetitors(tx: Tx, brandId: string): Promise<Competitor[]>
type Competitor = { id: string; name: string; kind: 'direct' | 'indirect' | 'aspirational';
  site: string | null; handles: Record<string, string>; adLibraryUrl: string | null; priority: number }

// domain/knowledge (base ships a stub that returns []; the brand branch replaces the body)
approvedFacts(tx: Tx, brandId: string, filter?: { section?: string }): Promise<ApprovedFact[]>
```

The research branch reads brand data only through `approvedFacts` and `listCompetitors`. Its own logic takes facts as an argument, so its tests pass facts in directly and never depend on the brand branch.

How the base implements them (helpers beyond the signatures above):

- Imports use `.ts` extensions; Node runs the TypeScript directly. `tenant_id` defaults from the transaction, so inserts set `brandId` only.
- A `NotFoundError` thrown inside `withBrand` rolls back and leaves the `denied` audit event itself. `audit` with a `brandId` needs a transaction scoped to that brand; without one the event is tenant-level. `tenantOf(tx)` (db/tenant.ts) gives the tenant ID for `objectKey`.
- Routers: `createRouter()`, `json()`, `errorResponse` (http/router.ts), `BrandParams` (http/brand.ts). Module routers are mounted at `/api` and declare full paths (`/brands/{brandId}/knowledge/…`). Pass the raw `brandId` to `withBrand`, which answers 404 for anything outside the tenant.
- Workflows: `QUEUE`, `retryWorkflow(id)` (forks from the first failed step). Tests: `launchTestWorkflows(t)` in test/helpers.ts; `testDb()` also returns `url`, `adminUrl` and `adminQuery`. `mockAi.reset()` and `mockAi.refusal` (queue it to make the model refuse).
- Tests that fetch from a local server swap `fetchGuard.resolve`, `isBlocked` and `minIntervalMs` (domain/sources/fetch.ts) and restore them after.
- Never import `drizzle-kit/api` in a test worker: it patches Array and String prototypes, which breaks pdf.js. The schema SQL comes from test/global-setup.ts. `drizzle-kit push` drops RLS `USING` clauses; use `pnpm db:reset` for a dev database.
- Web: shared components and the hooks `useBrandId`, `useBrand`, `useBrands` from `@/components/app`; `api` and `unwrap` from `@/lib/api/client`; the classes `btn btn-primary|secondary|quiet`, `field`, `label`, `input`, `panel`, `num` from app.css, which already scans `components/brand` and `components/research`. `pnpm e2e` starts the API (`server: pnpm e2e:server`, database `mkt_e2e_<port>`) and `next dev`, on `WEB_PORT` and `API_PORT`.

## 5. Shared web components (`components/app/`)

The base branch builds these. Both modules use them and do not restyle them.

| Component | Use |
|---|---|
| `Shell`, `PageHeader` | Layout; the active brand is always visible (FR-TEN-003) |
| `StateBlock` | One component for the loading, empty, partial, error, provider-unavailable, rate-limited and stale states (§17) |
| `StatusBadge` | Fact statuses and run states |
| `MoneyText` | An NPR amount, with USD in the title |
| `SourceQuote` | A quote with its source link or file and page |
| `CostConfirm` | Shows an estimate and the remaining monthly cap, and asks for confirmation |
| `RunProgress` | Polls a run every 3 seconds and shows its state, with cancel and retry |

Colours come from `web/public/theme.css` tokens through Tailwind names in `app.css`. No hex values in components. Type is Geist plus Noto Sans Devanagari.

## 6. Local environment

| Thing | Value |
|---|---|
| Node, pnpm | The installed Node 24 and pnpm 12.11.2. `engines` asks for Node 24 or later; production uses Node 26 |
| Containers | `colima start`, then `docker compose -f server/docker-compose.dev.yml up -d` |
| Postgres | `pgvector/pgvector:0.8.7-pg18` on 127.0.0.1:5436. Owner role `marketing` runs migrations; the app connects as `marketing_app`, which has no `BYPASSRLS` |
| Object storage | SeaweedFS with its S3 API on 127.0.0.1:8333, bucket `marketing-dev` |
| Ports | 3040 is taken on this machine. Base uses web 3140 and API 3141; brand uses 3240 and 3241; research uses 3340 and 3341. Read both from the environment |
| Tests | Each test file gets a throwaway database (`mkt_test_<random>`) and a fresh tenant from `test/helpers.ts`, so branches can run tests at the same time against one Postgres |
| Model | `AI_MODEL=mock` in every test and every agent run. No agent makes a paid model call |

Dependencies the base installs, so modules need not add any:

- `server/`: hono, @hono/node-server, @hono/zod-openapi, zod, drizzle-orm, drizzle-kit, pg, @dbos-inc/dbos-sdk, ai, @ai-sdk/anthropic, @aws-sdk/client-s3, @aws-sdk/s3-request-presigner, pino, sharp, a PDF text reader, a DOCX text reader, an HTML parser, a text-diff library, vitest. Versions are the ones pinned in `docs/stack.md` section 1 where it lists them.
- `web/`: @tanstack/react-query, openapi-fetch, openapi-typescript, @playwright/test.

## 7. Who builds what

| Step | Work | Model | Why this model |
|---|---|---|---|

| 1 | `product/base`, whole plan | Opus 5.5 | Tenancy, RLS, the fetch guard and the AI gateway are security-sensitive and everything builds on them |

| 2b | `product/brand`, web tasks | Sonnet 5.5 | Screens against a finished API and shared components |

Steps 2a and 2c start together once step 1 is merged-ready; 2b follows 2a in the same worktree. Worktrees live in `.claude/worktrees/brand` and `.claude/worktrees/research`.

Keeping token use down:

- An agent reads this file, its own plan and its own design. It reads the spec only at the line ranges its plan cites, and does not read `docs/stack.md`.
- One agent per branch phase. Tests are the gate for each task; there is no reviewer agent per task.
- Agents hand back a note of at most 150 words: what passed, what was skipped, base changes, added dependencies.
- All tests use the mock model.
